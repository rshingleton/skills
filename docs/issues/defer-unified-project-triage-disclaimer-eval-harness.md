## Context

Deferred by plan `doc-cycle-parallel` (README decisions 5 and 8, non-goals). Both items belong
to the separate unified skills project that vendors several upstream repos.

- `skills/engineering/triage/SKILL.md` (lines 13 to 16) requires every tracker comment to start
  with "This was generated by AI during triage." `plan-it/INTAKE-EVALUATION.md` dropped the same
  line in doc-cycle-parallel phase 3. `triage` is upstream-owned, so this fork does not edit it.
- An eval harness for skills (seen in `dietrichgebert/ponytail`) was considered and left out.
  Doc Cycle changes are checked today by headless `claude -p` dry runs against throwaway repos,
  recorded by hand in each phase's `execution-notes.md`.

## Problem / request

1. The repo rule says no AI attribution in anything that ships, but `triage` still posts an AI
   disclaimer on every tracker comment. Doc Cycle intake evaluation and triage disagree.
2. Skill behaviour changes have no repeatable check: each dry run is set up, run and read by
   hand, and cannot be re-run after an upstream merge.

## Acceptance (for planning)

- `triage` and plan-it's intake evaluation agree on the disclaimer, either through an upstream
  change or a vendoring override in the unified project.
- A skill eval harness can replay the Doc Cycle dry runs (plan-it, implement-it frontier,
  audit-it, verify-it, commit-it on a toy repo) and report pass or fail per step.
