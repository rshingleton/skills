## Which tracker?

Read `docs/agents/issue-tracker.md`:

- **Local markdown** (inbox `docs/issues/`) → [Local workflow](#local-workflow)
- **Jira REST** → [Jira workflow](#jira-workflow)

If both exist (local inbox + Jira for published plans), **triage** operates on the tracker named in `issue-tracker.md` as the intake system. Jira phase Tasks are **`/plan-it --jira`** only — not created here.

## Roles

Two **category** roles: `bug`, `enhancement` (local: `type: bug` | `feature` | `todo` | `defer`).

Five **state** roles: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`.

Map to tracker fields via `docs/agents/triage-labels.md`. One category + one state per item.

## Create issue

**Do not** create `docs/planning/`, phase prompts, or `jira.md` here.

| Tracker | Action |
|---------|--------|
| **Local** | Write `docs/issues/<slug>.md` per [issues-it](../issues-it/SKILL.md) + [INTAKE-TEMPLATE.md](../issues-it/INTAKE-TEMPLATE.md): `status: intake`, `source:` as appropriate (see below). |
| **Jira** | `POST /rest/api/2/issue?notifyUsers=false` — wiki `description`, `summary`, `issuetype` (`Bug` or `Task`), label `needs-triage`, optional `JIRA_ASSIGNEE`, **`timetracking`** (ask hours or `JIRA_DEFAULT_ESTIMATE_HOURS`). Then `_jira_apply_watcher_policy "$KEY" create`. |

### Email, ServiceNow, or pasted request (local inbox)

When the maintainer invokes `/triage` and **pastes** email or ServiceNow text (no file yet):

1. Work in the **application project repo** (not the ai-skills monorepo).
2. Derive `title`, `type`, and `slug` from the paste; ask if category is unclear.
3. Create `docs/issues/<slug>.md` with `source: email` or `source: servicenow`; optional `external_id:` (ticket number), `requester:`, `received:`.
4. Put the **verbatim paste** under `## Context`; distill **Problem / request** and minimal **Acceptance**.
5. Leave `status: intake` unless the paste is already fully specified (then `triaged` or `ready-for-plan` with maintainer confirmation).

Full org flow: [SCENARIO-EMAIL-SERVICENOW.md](../setup-internal-skills/SCENARIO-EMAIL-SERVICENOW.md).

Handoff:

> Created `docs/issues/<slug>.md` from pasted request. **Next:** review the file, `/triage` to refine, then `/plan-it --from-issues docs/issues/<slug>.md`.

## Local workflow

### Show what needs attention

Scan `docs/issues/*.md` (exclude `wontfix/` unless asked). Bucket by `status:`:

| Bucket | `status:` |
|--------|-----------|
| Needs triage | `intake` |
| In progress | `triaged` |
| Ready to plan | `ready-for-plan` |

Show title, slug, `type`, one-line summary. Oldest first within each bucket.

### Triage one file

1. Read `docs/issues/<slug>.md` and `## Comments`.
2. Explore codebase; read `.out-of-scope/` for similar rejections.
3. Recommend category + state role; wait for maintainer.
4. **Bugs:** attempt reproduction before grilling.
5. **Grill** if needed (`/grill-with-docs`).
6. **Apply:** update `status:` per [triage-labels.md](../setup-internal-skills/triage-labels.md); append `## Comments` with the disclaimer and triage notes.
7. **`ready-for-plan`:** remind maintainer → `/plan-it --from-issues docs/issues/<slug>.md`.
8. **`wontfix`:** optional move to `docs/issues/wontfix/<slug>.md`.

## Jira workflow

`source skills/engineering/setup-internal-skills/scripts/load-jira-env.sh` (or repo shim) before `curl`.

### Show what needs attention

Query Jira (oldest first):

```bash
# needs-triage
curl -s -H "Authorization: Bearer $JIRA_API_TOKEN" \
  "$JIRA_BASE_URL/rest/api/2/search?jql=project+%3D+$JIRA_PROJECT_KEY+AND+status+%3D+%22Open%22+AND+labels+%3D+needs-triage&maxResults=20"

# needs-info
curl -s -H "Authorization: Bearer $JIRA_API_TOKEN" \
  "$JIRA_BASE_URL/rest/api/2/search?jql=project+%3D+$JIRA_PROJECT_KEY+AND+status+%3D+%22On+Hold%22+AND+labels+%3D+needs-info&maxResults=20"

# ready-for-agent
curl -s -H "Authorization: Bearer $JIRA_API_TOKEN" \
  "$JIRA_BASE_URL/rest/api/2/search?jql=project+%3D+$JIRA_PROJECT_KEY+AND+labels+%3D+ready-for-agent&maxResults=20"
```

### Triage one issue

1. **GET** issue + comments.
2. **Recommend** category + state; wait for direction.
3. **Reproduce** (bugs).
4. **Grill** if needed.
5. **Apply** — resolve transition ID dynamically; **every** PUT/POST/comment URL uses `?notifyUsers=false`; after each write call `_jira_apply_watcher_policy "$KEY" update` (creates: `create`). If `JIRA_ASSIGNEE` set, `_jira_set_assignee` per [issue-tracker-jira.md](../setup-internal-skills/issue-tracker-jira.md#assignee-jira_assignee).

   ```bash
   curl -s -H "Authorization: Bearer $JIRA_API_TOKEN" \
     -H "Content-Type: application/json" \
     -X PUT \
     "$JIRA_BASE_URL/rest/api/2/issue/<KEY>?notifyUsers=false" \
     -d '{"fields": {"labels": ["ready-for-agent"]}}'
   _jira_apply_watcher_policy "<KEY>" update
   ```

   Outcomes:
   - `ready-for-agent` — agent brief ([AGENT-BRIEF.md](AGENT-BRIEF.md)); label `ready-for-agent`
   - `ready-for-human` — brief + why not delegable; label `ready-for-human`
   - `needs-info` — [needs-info template](#needs-info-template); `On Hold` + `needs-info`
   - `wontfix` — close or `.out-of-scope/` for enhancements
   - `needs-triage` — label `needs-triage`

6. **Doc Cycle handoff:** Jira-only bugs ready for a plan → suggest local intake (`/issues-it`) + `/plan-it --from-issues` if the repo uses an inbox; otherwise implement from Jira brief.

Status/label mapping: [issue-tracker-jira.md § Triage state mapping](../setup-internal-skills/issue-tracker-jira.md#triage-state-mapping).

## Quick state override

Trust explicit maintainer instructions ("move MT-42 to ready-for-agent"). Confirm, apply label/status, watcher policy. Skip grilling unless asked.
